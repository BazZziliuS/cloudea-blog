Здесь описан GitHub Actions workflow, который минифицирует Lua-код Garry's Mod сервера, собирает zip-архив и публикует его как релиз. Сама идея минификации и выбор инструмента взяты из поста [Garry's Mod - Минификация кода сервера](https://blog.amd-nick.me/gmod-minify) из блога _AMD_. Там деплой делается вручную скриптом, а здесь то же самое перенесено в CI.

## Зачем минифицировать

Клиентские и общие Lua-файлы сервер отправляет каждому игроку, и достать их можно, например, через ScriptHook. Минифицированный код читать заметно труднее, так что при утечке сборки или краже клиентских файлов разбираться в нём придётся дольше. Это не защита в строгом смысле, а усложнение работы для того, кто захочет код утащить.

Попутно уменьшается объём клиентского Lua, который сервер раздаёт игрокам. Насчёт ускорения запуска самого сервера AMD пишет осторожно, «в теории», и рассчитывать на заметный выигрыш не стоит.

## Перед началом

Репозиторий с кодом сервера должен быть приватным. Релиз на GitHub виден всем, у кого есть доступ к репозиторию, и в публичном репозитории это значит всем вообще. Как устроить такой репозиторий и что положить в `.gitignore`, разобрано в посте [Дружим Garry's Mod сервер и Git правильно](https://blog.amd-nick.me/2024/12/30/gmod-git-setup).

В архив попадает папка `cfg/`. Если в ней лежат `rcon_password`, токен `sv_setsteamaccount` или пароли от базы данных, вынесите их в отдельный файл, который не хранится в git, и подключайте на сервере через `exec`.

## Workflow

Что он делает:

1. Запускается, когда в репозиторий пушат тег вида `v*`, например `v1.0.0`.
2. Минифицирует все `.lua` файлы в `addons/`.
3. Удаляет из аддонов `.vscode` и `sftp-config.json`.
4. Склеивает все аддоны в один `superaddon`.
5. Собирает zip-архив и публикует его как GitHub Release.

```yaml
name: Build & Release

on:
  push:
    tags:
      - 'v*'

# Создание релиза требует права на запись: по умолчанию токен только читает.
permissions:
  contents: write

# Структура репозитория (корень):
#   addons/
#   cfg/
#   lua/
#   scripts/
#   sv.db
#   .gitignore

jobs:
  build-and-release:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout
        uses: actions/checkout@v4

      # Инструменты

      - name: Install Lua 5.3
        run: |
          sudo apt-get update
          sudo apt-get install -y lua5.3

      - name: Download glua-minify
        run: |
          curl -fsSL \
            https://raw.githubusercontent.com/xUnkNx/glua-minify/main/minify.lua \
            -o minify.lua

      # Минификация

      - name: Minify Lua files in addons
        run: |
          find addons -name '*.lua' -print0 | while IFS= read -r -d '' file; do
            if lua5.3 minify.lua minify "$file" > tmp_minified.lua 2> tmp_error.log; then
              cp tmp_minified.lua "$file"
            else
              echo "::warning file=$file::Minify failed, keeping original: $(head -n 1 tmp_error.log)"
            fi
          done
          rm -f tmp_minified.lua tmp_error.log

      # Удаление файлов разработки

      - name: Remove dev artifacts
        run: |
          find addons -name '.vscode' -prune -exec rm -rf {} +
          find addons -name 'sftp-config.json' -delete

      # Склейка аддонов в superaddon

      - name: Merge addons into single superaddon
        run: |
          mkdir -p superaddon_tmp
          for addon_dir in addons/*/; do
            [ -d "$addon_dir" ] || continue
            # Одинаковые пути в разных аддонах перезапишут друг друга: выводим их в лог.
            (cd "$addon_dir" && find . -type f) | while read -r rel; do
              if [ -e "superaddon_tmp/$rel" ]; then
                echo "::warning::Overwritten by $addon_dir: $rel"
              fi
            done
            cp -r "$addon_dir/." superaddon_tmp/
          done
          rm -rf addons/*
          mv superaddon_tmp addons/superaddon

      # Упаковка: только то, что нужно серверу.
      # .github, scripts и sv.db в архив не попадают.

      - name: Create release archive
        run: |
          TAG="${GITHUB_REF_NAME}"
          zip -r "release-${TAG}.zip" addons/ cfg/ lua/ \
            --exclude "*.git*"
          echo "RELEASE_ZIP=release-${TAG}.zip" >> "$GITHUB_ENV"

      # GitHub Release

      - name: Create GitHub Release
        uses: softprops/action-gh-release@v2
        with:
          name: "Release ${{ github.ref_name }}"
          generate_release_notes: true
          files: ${{ env.RELEASE_ZIP }}
```

Чтобы выпустить сборку, создайте и запушьте тег: `git tag v1.0.0 && git push origin v1.0.0`.

## Как это работает

Для минификации используется [xUnkNx/glua-minify](https://github.com/xUnkNx/glua-minify). Это форк `lua-minify`, который понимает синтаксис GMod: `!`, `!=`, `&&`, `||`, `continue`, комментарии `//` и `/* */`. Обычные Lua-минификаторы на таком коде ломаются. Глобальные имена он не переименовывает, поэтому `hook`, `net` и другие библиотеки остаются на месте.

Если файл не удалось разобрать, минификатор завершается с ошибкой, и в сборку уходит оригинал. Такие файлы видны в логе GitHub Actions как предупреждения с первой строкой ошибки.

Как и у AMD, минифицируются все `.lua` файлы в `addons/`, без деления на клиентские и серверные. Фильтр только по `cl_*` и `sh_*` в посте упомянут как возможное улучшение.

## Ограничения

Минифицируется только папка `addons/`. Файлы из корневой `lua/` попадают в архив без изменений. Папки `gamemodes/` в этой структуре нет вообще: если гейммод лежит в том же репозитории, его нужно добавить и в минификацию, и в команду `zip`.

Склейка в `superaddon` уменьшает число папок на сервере, но у неё есть цена. Если в двух аддонах есть файлы с одинаковым путём, например `addon.json` или одноимённый скрипт в `lua/autorun`, в сборке останется только последний по алфавиту. Workflow пишет такие случаи в лог предупреждениями. Если среди них есть Lua-файлы, переименуйте их или откажитесь от склейки.

## Отладка

Минифицированный код почти не читается, поэтому разбираться с ошибками удобнее на исходниках. AMD держит два сервера: DEV с исходным кодом и PROD, куда выкладывается только минифицированная сборка. Если нужно посмотреть код из сборки, его можно отформатировать через [GLuaFixer](https://github.com/FPtje/GLuaFixer) (`glualint --pretty-print-files`) или его расширение для VS Code.

## Откуда идея

Оба поста из блога _AMD_ ([blog.amd-nick.me](https://blog.amd-nick.me)):

- [Garry's Mod - Минификация кода сервера](https://blog.amd-nick.me/gmod-minify): зачем минифицировать код, почему подходит именно `glua-minify`, схема с DEV и PROD серверами и скрипт для ручного деплоя.
- [Дружим Garry's Mod сервер и Git правильно](https://blog.amd-nick.me/2024/12/30/gmod-git-setup): приватный репозиторий для папки `garrysmod`, что хранить в git, а что игнорировать, и работа с сервером через VS Code Remote SSH.

Схема с GitHub Actions и склейкой в `superaddon` моя, у AMD её нет.
